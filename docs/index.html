bench-kit
modules for research benches

Research benches for the close reading of code and texts in their versions

A research bench is a website for the critical reading of a program's source code, or of a text, across its surviving versions. It sets each version out line by line as it is held, compares any two, draws how they descend from one another, and lets a group annotate them together, with the documents that surround the program kept beside its code. bench-kit holds the modules the benches share. It began on 11 October 2026, when the Spacewar! and SHRDLU benches, which had until then copied code between them, were given one set of modules; the ELIZA bench followed, and the Melville bench, whose texts are prose, is the first to use the kit for something other than a program.

The kit is plain JavaScript and CSS, with no build step and nothing to install, served by GitHub Pages and released under the GNU General Public License (version 3). A bench includes it as a git submodule and gives its own names, texts and readers in a configuration file, so that what is particular to a program (its language, its machine, the way its files are assembled or run) stays in the bench and the rest is in common.

What a bench does

Read
Each version's files line by line, as held, with a search, the language highlighted, a citation for any line or range, a reading edition to print or save as Word, and export to Markdown.
Collate
Two versions collated as text, routine by routine, or, where both are Lisp, definition by definition, so that BBN-LISP's DEFINEQ and Maclisp's DEFPROP and DEFUN are read alike.
Book
For a text whose reader gives its structure (a TEI encoding, say): the text set as a page, a sheet to each page of the source with its image beside it; a version's states of revision as one text, with a slider through the stages; and Compare, a second text facing the first at the same page. A selection is the version's lines, so annotations are shared with Read.
Genealogy
A stemma of the versions, drawn as textual scholars draw the family of a text, and flows and trees of what each version keeps from its parent, moves, edits or drops.
Annotation
Through a private Hypothesis group, with replies, reactions and rich text. An annotation also shows, as a ghost, on the matching lines of the other versions.
Findings and My notes
Findings set out what the bench and the group have established, each with its evidence; My notes is a private tray of excerpts, figures and paragraphs gathered for writing.
Paratexts
Scans, documents, recordings and links in a private GitHub repository, catalogued in Dublin Core with Library of Congress, Getty and RDA terms, and arranged in collections, sequences and corpora.
Implementations
A public catalogue of a program's copies, ports, translations and reimplementations, with each one's parents, the route by which it came and the evidence for it, drawn as a tree and compared.
References
Every version and file has a short reference, and its source a Software Heritage identifier, so that a citation names the text as the bench read it.

The benches

SHRDLU

Terry Winograd, MIT Artificial Intelligence Laboratory, 1968–70 · MacLisp and Micro-Planner

SHRDLU took typed English and answered by moving blocks and pyramids on a simulated table with a simulated arm. The bench holds five versions, three of them as source: the MIT files as they were found on ITS, Winograd's Stanford distribution, and Eric Swenson's 2024 restoration for the PDP-10. A MacLisp reader indexes the sources, and an interpreter runs SHRDLU in the browser from each version's own files, recording every repair it needs in order to do so; Read marks those repairs in gold, after kintsugi.

The Graphics tab draws the blocks world from the program's own data file, each object's shape and colour from DISPLAY-AS and its place and size from ATABLE. The bench's catalogue of implementations holds 47 entries.

The Critical Code Studies SHRDLU project, led by David M. Berry and Mark C. Marino.

Spacewar!

MIT, 1961–62 · Macro assembly for the DEC PDP-1

The bench assembles each surviving version of the Macro source and runs it on an emulated PDP-1, the listing beside the scope following the program counter, with a trace, a profile, a record of the writes to memory, and breakpoints. The SHRDLU bench was first built from this one, and much of the kit, its frame among them, was written here before it was shared.

Collate sets two versions side by side, folding the lines they share. The catalogue of implementations holds 56 entries, the program's copies, ports and re-creations.

ELIZA

Joseph Weizenbaum, MIT Project MAC, 1964–66 · MAD-SLIP on the IBM 7094 under CTSS

The bench is built around the MAD-SLIP source recovered from Weizenbaum's papers in the MIT archives in 2021. It reads the program in layers: the DOCTOR script, ELIZA itself, and the SLIP routines ELIZA calls, each in its versions.

The Implementations tab, which the kit took from this bench, catalogues 138 implementations in their families, from Bernie Cosell's BBN-LISP DOCTOR of 1966 to the BASIC ELIZAs of the microcomputer magazines, and compares any two. Lisp texts are compared by definition, each read in its own dialect: BBN-LISP, PDP-6 Lisp, Interlisp, Maclisp or Common Lisp. The bench is the companion to Inventing ELIZA: How the First Chatbot Shaped the Future of AI (MIT Press, 2026).

Melville

Herman Melville, Billy Budd and the short tales · prose, from TEI

The first bench whose texts are prose. It reads the Melville Electronic Library's TEI of Billy Budd in the browser, from MEL's own repository at a fixed commit, and copies none of it into its own. From the one encoding it makes four versions: the manuscript before revision, the manuscript's last readings, a diplomatic text with every addition and deletion, and MEL's reading text. Each is divided leaf by leaf, so that Collate can set the manuscript beside the reading text one leaf at a time. The manuscript is in the Houghton Library, Harvard University (bMS 188 (363)).

The bench led to the kit's options for texts that are not code (no comment mark, the Collate modes a bench offers, its own words for its text) and to Book, which sets the TEI's structure as a page: the manuscript's revisions come and go as a slider moves through Hayford and Sealts's stages, each leaf's image beside its text, and the reading text can face the manuscript leaf by leaf. MEL's transcription is not reproduced on this page.

A research project of David M. Berry and Michael Jonik (University of Sussex).

Starting a bench

A new bench starts from bench-template, which runs on an invented example with the kit already in place.

  1. Make a repository from the template and clone it with its submodule.
  2. Put the sources under source/, a folder for each version.
  3. Describe the versions and how they descend in versions.js.
  4. Give the bench its names, its language and its references in config.js.
  5. Turn on GitHub Pages.
git clone --recurse-submodules https://github.com/YOUR-ORG/YOUR-BENCH

The template's README takes each step in turn, and the kit's README lists every setting and hook a bench can give.

How the kit changes

A change is made in the kit first and released with a version number and a tag; each bench then moves its submodule to that release when it is ready, and records the move in its own changelog. The kit's tests run in every bench on each push, so that a change which would break one of them shows before that bench takes it.

A feature written for one bench that would serve the others is moved into the kit. The Implementations tab came from ELIZA in this way, the Functional overview from the template, and the options for prose from Melville.
